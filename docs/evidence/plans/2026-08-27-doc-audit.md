# Documentation setup audit — 2026-08-27

Status: remediation in progress  
Scope: public repository polish; the canonical manifesto text is out of scope.

## Result

The repository already has unusually strong executable checks for its published
artifact, but it does not yet explain how public decisions, contributor routes,
release evidence, and UX behavior fit together. The remediation is therefore a
thin evidence layer around the existing document—not a documentation rewrite.

| Seam | Evidence | Finding | Remediation |
|---|---|---|---|
| Intent → decisions | No decision log or open-question home existed | A future maintainer cannot distinguish settled policy from unresolved work | Add `docs/DECISIONS.md` and `docs/OPEN_QUESTIONS.md` |
| Decisions → documentation | No documentation map existed | The same release fact can drift across README, changelog, feed, HTML, and tags | Add `docs/DOCMAP.md` with owners and propagation rules |
| Documentation → executable gates | Thirteen focused checks existed, but no documentation contract or aggregate required context | Excellent product checks were hard to protect as one branch rule | Add `scripts/check-docs.sh` and a required `validate` CI aggregate |
| Product → UX evidence | Public behavior existed only in implementation and tests | A reader path could regress without a human-readable scenario contract | Add compact public-reader scenarios and audit them against code |
| Product → contribution | Community profile was 62% complete; no conduct, support, issue, or PR routes | Objections and corrections had no structured landing place | Add a tailored community-health pack |
| Source → release | Annotated `v1.1` existed, while GitHub still presented `v1.0` as latest | Public version surfaces disagreed | Publish the existing `v1.1` tag as a GitHub Release |
| Source → governance | Default branch and release tags had no rulesets | The repository's strongest invariants were advisory | Protect `main` and `v*`, require the aggregate check, and keep linear history |
| Source → delivery | GitHub Pages reported HTTPS enforcement off while the live edge redirected to HTTPS and served HSTS | Repository settings and observed delivery disagreed | Enable Pages HTTPS and re-run the live acceptance gate |

## Gate planted before remediation

`scripts/check-docs.sh` must reject a temporary copy in which a required
governance file is removed. CI may call the same command; it must not maintain a
second list of required documentation.

## Proof required to close

- the documentation checker passes and its planted missing-file case fails;
- the existing local, render, negative, and live suites remain green;
- the UX linter and coverage audit pass;
- the merged commit is protected by a required aggregate check;
- GitHub reports `v1.1` as the latest release and Pages HTTPS as enforced.
